# DICOM 影像批量下载工具（Windows 可视化版）

读取 Excel 表格中的一列标识（StudyInstanceUID 或 病人ID），通过 **DICOM Q/R 协议**（C-Find + C-Move）
从医院 PACS 批量拉取影像到本地目录，所有连接参数可视化配置。

> 协议依据：众阳云开放服务 API「2.8.1.3 获取检查图像」—— DICOM 3.0 Q/R
> C-Move 入参：StudyInstanceUID (0020,000D)

---

## 一、⚠️ 关键：查询键必须是下面两种之一

众阳 PACS 的 C-Find / C-Move **只支持**两个查询键：

| 可用的键 | DICOM 标签 | 你 Excel 里对应的列 | 是否可用 |
|---------|-----------|------------------|---------|
| **StudyInstanceUID** | (0020,000D) | 形如 `1.2.840.xxx...` 的列 | ✅ 精确到一次检查 |
| **patientId / 病人ID** | (0010,0020) | 「病人ID」列（如 `1554033`） | ✅ 一病人可能对应多次检查 |

> ⚠️ **「影像号」这一列不能直接当作查询键！** 医院导出的「影像号」是纯数字流水号（如 `1006567`），
> 它在 DICOM 里是「检查号 AccessionNumber」，**不在众阳支持的查询键里**。
>
> 本工具支持「影像号」列名仅作为默认占位列名，**实际查询必须用 StudyInstanceUID 或病人ID**。
> 推荐让医院/众阳工程师在导数据时补一列 **StudyInstanceUID**（或提供「影像号 → StudyInstanceUID」映射表），再按 UID 精确下载。

### 两种查询模式

| 模式 | 输入列 | 下载结果 |
|------|--------|---------|
| `StudyInstanceUID(影像号UID)` | UID 所在列（默认列名「影像号」可改） | 每个 UID 精确拉一次检查 |
| `病人ID(patientId)` | 病人ID 列 | 先 C-Find 查该病人**全部检查**，再逐个拉取（可能多拉） |

## 二、主要功能

- 可视化配置 PACS IP / 端口 / AE Title、本机 AE Title / 接收端口
- **检测连通（双向）**：正向 TCP + DICOM C-Echo；反向自检（经本机外部 IP 连自己的接收服务并 C-Echo）+ 前置机反向探测（发空 C-Move 观察前置机是否主动连入）
- **查询键两种模式**：StudyInstanceUID 精确拉取 / 病人ID 展开后逐个拉取
- **串行下载**（稳态，避免给前置机造成并发压力）
- **间隙暂停**：每下载 N 个检查后暂停 M 秒，给 PACS 喘息
- **限速**：按 KB/s 节流 C-STORE 落盘速率（限速通过延迟应答实现，过低会触发单文件 2 秒封顶保护，避免前置机判超时）
- **进度显示**：总进度条 + 当前检查的「影像数 X / N」+ 已耗时
- **下载报告**：每次下载生成 `下载报告_YYYYMMDD_HHMMSS.csv`（UTF-8 with BOM）
- **手动停止**：中断当前 association，剩余任务不再处理
- **优雅退出**：关闭主窗口时主动 shutdown Store SCP，避免 Windows 端口 TIME_WAIT
- **独立「脱敏配置」区块**（与「下载配置」分离，两个开关相互独立）：接收 C-STORE 时直接在内存中处理，**落盘即为脱敏后的影像**，无需事后再跑单独的脱敏程序
  - **模块① 标签脱敏**：**规则完全可配置**——逐条选择「DICOM 标签」+「脱敏方法」+「参数」+「作用范围」，界面维护、随 `config.json` 保存（规则见「十一、脱敏规则」）
  - **模块② 剂量报告/截屏过滤**：**规则完全可配置**——逐条选择「DICOM 标签」+「匹配模式（精确/包含/正则）」+「命中值」；并提供「**保存命中的过滤影像**」开关，勾选则命中项存入 `输出目录/_剂量报告/` 子目录，不勾选则命中项直接丢弃不落盘
  - **按需展开**：两个模块均只有勾选「启用」后才展开详细规则配置，未勾选时仅显示开关，界面更简洁
- **私有标签容错（宽容解析）**：部分厂商的私有标签长度与 VR 不匹配（如 `(01F1,1026)`），pydicom 严格模式会因单个标签导致**整份文件解析失败**；工具已启用宽容解析（`convert_wrong_length_to_UN`），此类标签按原始字节保留，再交给「清空私有标签」规则处理，不会造成文件被拒
- **未落盘文件留痕**：因解析/脱敏异常被拒绝落盘的文件，单独生成 `未落盘文件清单_*.csv`，并在日志与下载汇总里给出总数
- **脱敏审计日志（Excel）**：开启模块①后自动生成 `脱敏审计_*.xlsx`，逐字段记录脱敏前后对比，主键为影像保存的文件名；只记实际变化的字段，原始 PatientID 不写入

## 五、运行前需向医院（众阳）确认/索取

| 项 | 填写位置 | 说明 |
|----|----------|------|
| PACS 前置机 IP | 「PACS IP」 | 医院影像归档前置机地址 |
| PACS 端口 | 「PACS 端口」 | 通常 104 或自定义 |
| PACS AE Title | 「PACS AE Title」 | 前置机的 DICOM AE Title |
| 本机 AE Title | 「本机 AE Title」 | 自定义，如 `CLIENT_AET`（1~16 位 ASCII，不能含空格/中文） |
| 本机接收端口 | 「本机接收端口」 | 自定义，如 `11112`（**不能落在 Hyper-V/WSL 排除范围**） |
| **节点注册** | —— | 把「本机 AE Title + 本机 IP + 接收端口」交给工程师，注册进前置机并开通 Q/R 权限 |
| **网络** | —— | 运行电脑需能访问前置机 IP:端口（内网 / VPN / 白名单） |
| **StudyInstanceUID 列** | —— | 想精确下载必须由工程师在导出数据时补这一列 |

> ℹ️ 本机 IP 会显示在「检测连通」结果中，请把它（而非 127.0.0.1）报给工程师注册。

## 六、使用步骤

1. **填好 PACS 与本机参数**（首次可点「保存配置」记到 `config.json`）
2. 点「**检测连通**」—— 双向检测：正向 TCP + C-Echo；反向自检 + 前置机反向探测，任一失败都会给出可操作建议
3. **「浏览...」选择 Excel**（`.xlsx` / `.xlsm`；Excel 需先关闭，否则会报「文件被占用」）
4. **选「查询键类型」**，并在「关键列名」填写对应列名（默认「影像号」，可改为 `StudyInstanceUID` / `病人ID` / `A` / `1` 等）
5. **选择输出目录**（下载报告 CSV 会写入该目录）
6. 高级参数可保持默认：
   - C-Move 超时 300 秒 / C-Find 超时 60 秒
   - 限速 0 = 不限；每 0 个检查暂停 = 不暂停
   - 「诊断日志」默认关闭：只输出关键日志；勾选后输出 PDU/协商/Pending 细节，排查问题时使用
7. **按需配置「脱敏配置」区块**（独立于下载配置；开关默认均关闭，下载开始时一次性生效，中途改复选框不影响本次任务）：
   - 区块自上而下依次为「**模块② 剂量报告/截屏过滤**」→「**模块① 标签脱敏**」（与执行顺序一致：先过滤、后脱敏）
   - **未勾选时只显示启用开关，不展开详细规则**；勾选后才会展开对应的规则表与选项：
     - **模块②**：展开「保存命中的过滤影像」开关 + 过滤规则表；规则表可「添加/编辑/删除/恢复默认」，**双击行可编辑**
     - **模块①**：展开全局选项（清空私有标签 / 所有日期压缩到「年-月-01」/ 所有时间清空）+ 标签脱敏规则表；同样可增删改、恢复默认、双击编辑
   - 勾选启用后落盘即为脱敏影像（文件夹名仍用影像自带的原始 `PatientID`）
   - ⚠️ 下载进行中会禁用规则的增删改按钮，避免中途改配置导致前后不一致
8. 点「**开始下载**」；日志实时输出每个 Study 的 C-Move 最终状态与结果
9. 下载结束自动弹出汇总（成功 / 失败 / 共），并生成报告 CSV

> 「**下载记录**」按钮可查看本次明细，「**导出 CSV**」可保存到任意位置。

## 七、下载报告

- 每次下载结束会在输出目录生成 `下载报告_YYYYMMDD_HHMMSS.csv`（UTF-8 with BOM），包含序号、查询键、StudyInstanceUID、结果、文件数、说明、时间。
- 若有文件因解析/脱敏异常被拒绝落盘，另生成 `未落盘文件清单_YYYYMMDD_HHMMSS.csv`（StudyInstanceUID、SOPInstanceUID、失败原因、时间），日志与完成弹窗也会给出总数。
- 开启**模块① 标签脱敏**时，自动生成 **`脱敏审计_YYYYMMDD_HHMMSS.xlsx`**：逐字段记录**脱敏前后对比**，主键为影像保存的文件名，列为「影像文件名 / StudyInstanceUID / 脱敏后PatientID / 标签 / 关键字 / VR / 脱敏方法 / 脱敏前 / 脱敏后 / 时间」。只记录**实际发生变化的字段**，私有标签清空按影像汇总成一条。

> ⚠️ **脱敏审计 Excel 含脱敏前的原值**（`PatientID` 除外，只记录脱敏后的值），属于敏感文件。
> 请勿与脱敏后的影像一起对外交付，按要求单独归档或使用后删除。
> 明细先写入输出目录的 `_脱敏审计明细.tmp.csv`，下载结束转成 Excel 后自动删除该临时文件（转换失败则保留，避免数据丢失）。

- 失败/停止的 Study 不会自动跳过，重新运行即会再次拉取。

## 八、常见问题

| 现象 | 原因 / 处理 |
|------|-----------|
| 「检测连通」TCP 失败 | IP/端口错误、网络不通、需 VPN/白名单 |
| TCP 成功但 C-Echo 失败 | AE Title 不正确，或前置机未放行本机 IP |
| 报 `Move Destination unknown` (0xA801) | 本机 AE Title 未注册到前置机 |
| 报 `Out of Resources` (0xA700) | 查询条件不匹配 / 该 UID 不存在 |
| 「检测连通」提示「端口无法绑定」 | 端口被占用 / 落在 Hyper-V/WSL 排除范围 / 被防火墙拦截。提示中给出 `netsh` 命令与处理建议 |
| C-Move 状态成功但 0 个文件 | 前置机是「先返回成功、异步推影像」特性，工具会多等 30 秒；若仍 0 文件，大概率是本机注册 IP/端口与前置机侧不一致 |
| C-Move 状态为 0xB000（部分失败） | 少数影像子操作失败，工具按**本地已落盘文件数**记为成功；如有个别缺失，重跑该 Study 即可全量补拉 |
| 用「影像号」查几乎全失败 | 影像号不是有效查询键，改用 StudyInstanceUID 或病人ID |
| Excel 报「文件被占用」 | 关闭 Excel 后再试 |
| exe 被 Windows 拦截 | 右键属性 → 勾选「解除锁定」，或 SmartScreen 选「仍要运行」 |
| 关闭主窗口后端口残留 TIME_WAIT | 工具已主动 shutdown Store SCP；若仍有残留，等 30~60 秒或换个端口 |
| 开启模块①后输出文件夹名会变成哈希吗 | 不会。文件夹始终按影像自带的**原始 `PatientID`** 命名（脱敏只改文件内的标签，不改目录名） |
| 想确认某检查里的剂量报告/截屏被过滤 | 开启模块②后，命中文件在 `输出目录/_剂量报告/<PatientID>/`，日志会打印每个检查的命中数量 |
| 想脱敏/过滤别的标签 | 在「脱敏配置」区块对应规则表点「添加规则」，选标签（可下拉或手输关键字/Tag 号）再选方法/模式即可，无需改代码 |
| 不想要命中的过滤影像 | 取消勾选模块②的「保存命中的过滤影像」，命中项将直接丢弃不落盘（该检查若全部命中仍算成功，不会被 PACS 重发） |
| 脱敏审计 Excel 里能看到原始 PatientID 吗 | 看不到。原始 PatientID 不写入日志，只记录脱敏后的值；其它实际变更字段会记录前后对比。注意该表明文含原值，属敏感文件，需单独归档 |
| 同一个标签加了两条规则听谁的 | 只生效第一条；界面新增/编辑同标签规则时会自动移除旧规则 |
| 汇总提示「另有 N 个影像处理失败未落盘」 | 这些文件在接收时因解析/脱敏异常被拒绝落盘（不会写出未处理的原始影像），明细见输出目录的 `未落盘文件清单_*.csv` |
| 报 `Expected total bytes to be an even multiple of bytes per value` | 厂商私有标签长度与对应 VR 不匹配，pydicom 严格解析报错（旧版脱敏程序常因此整批失败）。工具已启用宽容解析，此类标签按原始字节保留并由脱敏规则清空 |

## 十一、脱敏规则（界面可配置）

两个模块相互独立，可单独或同时开启，统一放在**独立于「下载配置」的「脱敏配置」区块**中维护。
区别是在 **C-STORE 接收时直接处理内存中的 Dataset**，因此落盘即为处理后的影像。

> **执行顺序固定为「先过滤、后脱敏」**：过滤常依赖 `SeriesDescription` 这类会被脱敏清空的字段，
> 顺序反了就永远匹配不到。
>
> **规则冲突**：同一标签只生效第一条规则；在界面新增/编辑时会自动移除同标签的旧规则，保证行为唯一可预测。
>
> **计数说明**：接收数（含被按规则丢弃的文件）≠ 落盘数；即使某检查的影像全部命中过滤被丢弃，
> 只要接收数 > 0 仍判定为成功，避免 PACS 重发。

### 模块① 标签脱敏（默认关闭）

规则表每行 = 一个「DICOM 标签」+ 一种「脱敏方法」+「参数」+「作用范围（仅顶层 / 递归到序列内）」。

**标签填写方式**（下拉可预选常用标签，也可直接手输关键字或 Tag 号）：

- 关键字：如 `PatientName`、`StudyID`
- Tag 号：如 `0010,0020`、`(0010,0020)`、`0010 0020`

**支持的脱敏方法（7 种）**：

| 方法 | 说明 | 参数 |
|------|------|------|
| 哈希（SHA512 截断） | SHA512 十六进制摘要截断，**不加盐**，跨批次同明文同哈希 | 截断位数，默认 16 |
| 固定值替换 | 把标签值替换为指定字符串 | 替换为（留空 = 置空） |
| 清空该标签 | 把标签值置为空串 | 无 |
| 删除该标签 | 直接把该元素从 Dataset 中移除 | 无 |
| 出生日期 → 年 + 0101 | 取前 4 位年份再拼 `0101`，如 `19700215` → `19700101` | 无 |
| 日期 → 年-月-01 (DA/DT) | 如 `20240115` → `20240101` | 无 |
| 时间清空 (TM) | 把时间值置空 | 无 |

**全局选项（各可独立开关，默认都开）**：

| 选项 | 说明 |
|------|------|
| 清空私有标签 | 清空所有私有（odd group）标签，含序列内 |
| 所有日期压缩到「年-月-01」 | 对所有未单独配置规则的 `DA`/`DT` 统一压缩 |
| 所有时间清空 | 对所有未单独配置规则的 `TM` 统一清空 |

**默认规则（点「恢复默认规则」即还原为下表）**：

| 脱敏方法 | 标签（作用范围） |
|---------|----------------|
| 哈希（16 位） | `AccessionNumber`（仅顶层）；`PatientID`、`StudyID`、`ScheduledProcedureStepID`、`PerformedProcedureStepID`（递归到序列内） |
| 固定值替换 | `PatientName`→`ANONYMOUS`；`InstitutionName`→`Shandong_Class3B_2_Hospital`；`InstitutionAddress`/`ReferringPhysicianName`/`OperatorsName`/`RequestingPhysician`/`OtherPatientIDs`/`PatientAddress`/`PatientTelephoneNumbers`/`InstitutionalDepartmentName`/`StationName`/`StudyDescription` → 空 |
| 出生日期 → 年 + 0101 | `PatientBirthDate` |

> **关联 UID 不脱敏（默认规则未包含，故保持不变）**：`StudyInstanceUID` / `SeriesInstanceUID` / `SOPInstanceUID`，
> 确保脱敏后仍是一套完整、可正常浏览的检查。若确有需要，可自行添加规则将它们一并处理。
>
> **文件夹名**：始终按影像自带的**原始 `PatientID`** 命名（缺失时回落到 `StudyInstanceUID`），
> 与是否开启模块①无关——即使开启了标签脱敏，文件夹名也不会变成哈希值。
>
> **安全兜底**：脱敏过程中若发生任何异常，该文件会被拒绝落盘（不会写出未脱敏影像）。

### 模块② 剂量报告/截屏过滤（默认关闭）

规则表每行 = 一个「DICOM 标签」+「匹配模式」+「命中值（多个值任一命中即可）」。

**匹配模式（3 种）**：

| 模式 | 说明 |
|------|------|
| 精确匹配 | 整值相等（多值字段按 `\` 切分后逐段比对，不区分大小写） |
| 包含匹配 | 值中包含关键字即命中 |
| 正则匹配 | 按正则表达式匹配；**正则非法时自动降级为包含匹配**，保证程序不中断 |

**保存命中的过滤影像开关**：

- **勾选（默认）**：命中项存入 `输出目录/_剂量报告/<PatientID>/`，与正常影像分开存放（不丢弃）
- **不勾选**：命中项直接丢弃、不落盘（接收计数照常，不返回失败，避免 PACS 重发）

**默认规则（点「恢复默认规则」即还原为下表）**：

| 规则 | 标签 | 模式 | 命中值 |
|------|------|------|--------|
| Image Type | (0008,0008) | 精确匹配 | `SCREEN SAVE`、`SCREENSAVE` |
| Series Description | (0008,103E) | 精确匹配 | `DoseReport`、`Dose Report`、`BBS_Display`、`BPM_Display` |

日志与下载报告的「说明」列会注明本次检查命中的过滤文件数。
